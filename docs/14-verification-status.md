## 14. Verification status

What has been checked, so you know how far to trust this document:

- **Checked by running it (last check: 2026-11-04):**
  - the date model: 48 000 random round trips of all eight formats in `app/js/dates.js`; 30 000 random ISO time stamps (years −99000 to +99000) read back identically by JavaScript's own `Date.parse`; 25 600 test vectors and 2 020 time stamp strings (accepted and refused spellings) giving the same answers in JavaScript and in `service/dates.php` (alignment, end of period, old-data conversion, upgrade of seconds to ISO text, error cases);
  - `service/store.php` on a copy of the sample data: migration of the old format (50 conversions, 0 on a second run), conversion of data in the previous release's format (seconds to ISO text, in places and in notes), unknown languages refused for names and notes, adding a language (and its error cases), mountain height (valid, empty, too high, not whole), optional dates, a time stamp that does not match its format, notes with and without a date, and the rebuilt search index;
  - the interface in a headless browser against the development server (language tab and its add form, language selects in the place and note forms, date field with several formats and ranges, "31 February" refused, mountain with and without height, server refusing an unknown language). In that browser test the map library was replaced by a stand-in, so map drawing was not exercised.
- **Layers (2026-11-04):** `store.php` 81 checks; the controller with stand-ins for phpBB 29 checks (permissions, not a live phpBB); the Node dev server 75 checks; the interface in a headless browser (map library stubbed) 22 checks: Maps tab rename, Only / Hide, layer search, categories add and rename, create layer, choose places, layer note, new place joins the open layer with a tagged note, leave a layer, delete a layer. Ring colours and clicking markers on the real map were **not** exercised (stub).
- **Not re-checked in the last round:** the Node dev server's answers compared one by one with PHP's for the older features. Overlays and the guest view were not changed.
- **Not verified by me:** behaviour inside a live phpBB installation (the login gate, the administrator check, the Quick links entry and route generation). The extension owner has run earlier versions on a forum; each update should be tried there first.
- **Not verified:** the outside services (base map, satellite, search, directions) could not be reached from the environment used for testing, so their addresses and terms were checked against their documentation and were not exercised live from there.
- **Tests:** PHP `tests/php/` (`php tests/php/run.php`: 93 tests), data `tests/data/` (`php tests/data/run.php`: 38 tests; `php tests/data/run.php <store>` checks a live store, read only) and JavaScript `tests/js/` (`node tests/js/run.js`: 53 tests, incl. real-browser scenarios), all passing on 2026-11-05. The CSS/HTML part is planned in `tests/README.md`. The browser and Node scripts mentioned above are still **not** in the repository.
- **Relief layer (2026-11-15):** checked by running: the terrain tile maths, Terrarium round trip, averaging pyramid, bilinear Web Mercator sampling against a formula, an end-to-end build of a synthetic DEM, resuming after an interruption, `NOTICE.txt`, `.htaccess`, zip and preview (`tools/terrain/test_terrain.py`), and the dropdown entry, source and layer settings with a MapLibre stand-in (`tests/js/map.test.js`). **Not verified:** reading real GeoTIFF files, the real AWS file names, Apache and Cloudflare behaviour, real tile sizes, how the relief looks on a real map, speed on weak phones.
- **Larger area and the terrain tool (T-060, 2026-11-15):** checked by running: the tile and square counts of the new `bbox` (285 squares; 4,040 / 15,812 / 62,250 tiles at zoom 0-10 / 0-11 / 0-12), the rule that only HTTP 404 means "no tile" (fake downloader: 403, 5xx, URL error, timeout and reset stop the run), the refusal to build with squares never downloaded, the `squares` notes, the mixed GLO-30 / GLO-90 mosaic window arithmetic and the open-file limit (with a stand-in for rasterio, which assumes GDAL maps output pixel centres into the source), `preview --at`, and the search `viewbox` built from the config. **Not verified:** that GLO-30 for Armenia and Azerbaijan is absent in the real bucket (404, as three sources say) and not present with void parts; real GeoTIFF reading, real S3 answers (404 versus 403 for a missing key), real tile and download sizes, build time, memory, how the 30 m / 90 m seam looks, relief on the real map canvas (MapLibre cannot be loaded here), the file limit of the real host.
- **Relief from AWS tiles (2026-11-15):** only the config values and the lazy source are tested (`tests/js/map.test.js`). NOT checked: that `elevation-tiles-prod` answers, sends CORS headers, serves the Armenia area, the attribution wording, the look on a real map.
- **Flat colour bands (2026-11-16):** the expression is an `interpolate` with paired stops 0.01 m apart (a `step` was not chosen: not checkable here). UNVERIFIED on a real map: flat colour in a band, sharp edge, no stripes, a limit on the number of stops, with adapt on and off.
- **Relief credit, bounds and GLO-90 (2026-11-16):** tested against the MapLibre stand-in and with fake downloads only. NOT checked: why the owner did not see MapLibre's own credit (the library cannot be loaded here), the look of the credit text under the base-map list at 390 px, the GLO-90 file names and bucket, the exact GLO-90 credit wording (read through a summarising fetch, not raw text), every size of the GLO-90 table (synthetic terrain).
- **3D view (T-056, 2026-11-17):** tested against the MapLibre stand-in only: `maxPitch` 85, sliders call `setPitch`/`setBearing`, map events move the sliders, Flat/Tilt 60/North up, `setTerrain` gets the source and the exaggeration and is cleared, one shared terrain source in either order, saved values read again and bad ones ignored. NOT checked: how the terrain looks on a real map, a real mouse or two-finger drag, that the HTML place markers stay at the right spot when tilted, speed on a phone.
- **Relief colours (2026-11-15):** tested against the MapLibre stand-in only: layer type and order, ramp expression (sorted, repeated height nudged), controls, legend, height decoding and tile choice with mocked fetch. Contour smoothing (grid blur and corner cutting) and the colour slide (fake clock) are tested on small data. NOT checked: how the lines look on a real map, speed of the 128 x 96 grid on a phone. Ramp editor, contour lines (marching squares, tested on small grids and a mocked tile), height profile (mocked tile) and saved settings are tested against the stand-in only; NOT checked: how they look and feel on a real map and on a phone. The adaptive colour range (view heights from a 16 x 16 grid, 2nd-98th percentile) is tested with a mocked tile. NOT checked: the real MapLibre 5.24.1 (rendering of `color-relief`, the whole map after the 4.7.1 -> 5.24.1 upgrade), the look of the colours, CORS of the tile server for the height readout.
- **Time bar (2026-11-16, T-040):** tested with the stand-ins only: the rule (`visibleAt`, table of cases), the state key, the filters, play steps, the `faded` property in the layer paint. NOT seen: the bar on a real page (layout, phones), the faded look on a real map, the date field inside the bar.
